# condor_fit/ 目錄結構（2026-09-06 整理）

| 目錄 | 內容 |
|---|---|
| `backups/` | 每次調參前的產物備份（32 個，依日期與 bin 命名）。含 `stale_web_archive_20260906/`（從網站清掉的 136 張舊 binning 圖）。 |
| `log_archive/` | condor job log 與 eos_retry log 的壓縮封存。原本散檔 1.45 GB，壓縮後 218 MB。 |
| `scratch/`, `localtest/`, `logs_bin/` | 臨時測試輸出。 |
| 頂層 `*.log` | 個別重跑的 log（本輪保留最近 7 天，更早的在 log_archive）。 |

## 從封存取回 log

    tar -tzf log_archive/condor_logs_20260906.tar.gz | grep <cluster-id>
    tar -xzf log_archive/condor_logs_20260906.tar.gz logs/<file>.log

封存內容已逐檔驗證：檔案數與原檔相符（2335 / 282 / 76），抽驗 md5 一致。

## 為什麼 fit_diagnostics/ 不再被 git 追蹤

它是每次擬合都重生的輸出（18148 個檔）。追蹤它會讓 `git status` 永遠掛著
5739 個 modified，實質上讓 git 看不出真正的程式碼改動。2026-09-06 用
`git rm --cached` 取消追蹤並加進 .gitignore，**檔案本身保留在磁碟上**。
